# 扫码配网与 OTA 确认（固件 0.10.9）

本轮仅修改源码、编译和执行离线回归。没有操作实际设备、切换网络、上传 OTA 或部署服务。随后按用户要求通过 USB 安装了 0.10.7、0.10.8 和 0.10.9；手机自动弹页、无线扫描、密码错误处理和 OTA 重启/回退仍待实机验收。

## 配网流程

1. 设备 `SETTINGS → NETWORK → Connect Wi-Fi` 进入配网。首次没有已保存网络、或尝试全部已保存网络失败时也会进入配网。
2. 手机用系统相机扫 **JOIN HOTSPOT**，确认加入 `mic-on-XXXX`。这是加入设备热点的 Wi-Fi 二维码，不是要求用户先访问一个不可达的内网网址。
3. 手机关联热点后，设备自动显示第二步。手机通常会弹出 Wi-Fi 登录/配置页；没有弹出时使用屏幕上的备用网址二维码 `http://192.168.4.1/`。自动弹页由手机系统决定，不能保证所有机型或第三方扫码器一致；设备短按 OK 仍可切换两张码。
4. 页面自动扫描附近 2.4 GHz 网络，按信号强弱排列，显示密码/开放网络。相同 SSID 与开放/加密类型的记录合并，保留最多 24 条扫描记录中的可用结果；隐藏网络保留手动输入入口。企业认证、WEP 和旧 WPA-only 网络不作为可选项。
5. 点选网络、输入密码，点击 **CONNECT**。开放网络不要求密码。设备热点保持运行，网页轮询连接状态。
6. 取得目标网络的 IP 后才保存到 NVS，显示连接成功、网络名和设备地址。密码/认证失败、找不到 AP、连接或 DHCP 超时、存储失败都会显示可重试结果。失败不覆盖已有凭据，不自动重启。
7. 成功后点击 **FINISH & RESTART**，设备重启进入正常使用。手机重新加入日常 Wi-Fi；其后设置页面需要手机与设备能在局域网互相访问。若热点与目标路由器频道不同，单射频切换可能使手机短暂重新关联，页面会继续尝试读取状态。

已联网设置页新增 **CONNECT ANOTHER NETWORK**。确认后设备重启进入上述热点流程；旧的“填名称直接保存并重启”入口取消。这是为了让更换网络的连接结果仍能在手机上显示，而不是切断原局域网连接后丢失页面。历史保存的网络仍可删除，最多保留八个。设置页的内网地址二维码明确标为 **OPEN SETTINGS**，与加入配网热点的二维码区分。

配置当前手机自己的热点时，需要另一部手机或电脑操作配网页，让目标手机热点在连接检查期间保持开启。隐藏或暂时不存在的网络可以手动输入名称，但本轮不提供“跳过连接验证直接保存”；目标网络必须能实际连接并取得 IP。

## 固件实现与边界

- 配网使用 AP+STA，并初始化 STA 网络接口与 IP/Wi-Fi 事件；原有纯 AP 路径不能直接完成扫描和试连。
- 扫描、试连和历史网络重试共用无线操作所有权。网页发起操作后接管配网，暂停后台自动重试；即使历史网络恰好在这时接通，也不会抢先重启设备。
- 扫描异步启动，HTTP 返回后由网页查询结果；读取结果后释放驱动扫描列表。结果数量有界，不在 WebSocket 语音期间扫描。
- 凭据测试等待 IP 或断开事件，最长 20 秒。网页显示的认证错误不武断等同于“密码错误”，因为路由器策略等也可能造成认证失败。
- 热点 DNS 引导与 HTTP 302 将系统探测请求转到设备的统一配网地址。关键 POST 请求要求本次配网的随机 nonce，网络名称以纯文本写入页面。
- `GET /api/setup` 返回连接状态与配网 nonce；`POST/GET /api/scan` 启动/查询扫描；`POST /configure` 试连或删除；`POST /finish` 仅在连接并保存成功后安排重启。接口仅在配网热点模式提供，重启后恢复正常设置服务。
- USB 直接保存 Wi-Fi 的工程入口保留；它不属于网页连接验证流程。

## 旧固件的网页 OTA 上传与确认

旧固件支持本地网页上传；0.10.9 起使用设备按钮自动下载入口，见下文。

1. 以下仅适用于 0.10.8 及更早固件：进入当时的 Web setup / update 入口开放五分钟上传窗口。0.10.9 已删除该入口，日常升级使用 DEVICE → Firmware update。
2. 选择 `passport-gpt-live.bin`。网页读取镜像头与应用描述，检查项目名，显示目标版本。不要上传 bootloader、分区表或全片镜像。
3. 上传进度达到 100% 仅代表上传进度。设备完成镜像校验与写入后返回待启动的版本/镜像标识，屏幕显示 **FIRMWARE SAVED / Restarting to verify**。
4. 网页保留待确认信息并等待设备重启，核对同一设备 ID、新启动 ID、目标版本、完整 ELF SHA-256 镜像标识及 OTA 启动状态。只有全部一致且启动状态为 `valid` 才显示 **UPDATE CONFIRMED**；同版本不同构建也不会混淆。
5. 新固件尚待启动确认时继续等待；重启后版本/镜像不同则提示未确认或可能回退。上传响应丢失会尝试读取重启结果，不能直接推定成功或失败。HTTP 明确拒绝上传则显示错误并恢复按钮。
6. 最多自动等待三分钟；之后提示重新接回同一 Wi-Fi 并刷新检查，不自动重新上传。待确认信息保存在当前站点的 sessionStorage（浏览器允许时），刷新页面后继续查询。若 IP 改变或设备进入配网模式，原页面可能无法自动找到设备，此时需要打开新地址并人工核对；不会把超时当成功。

`GET /api/info` 新增 `device_id`、`boot_id`、`image_id`、`ota_state`、`update_seconds`。其中 `image_id` 是应用描述中的完整 ELF 哈希，不是 `.bin` 文件的 SHA-256；启动确认不证明音质或业务功能已经验收。

**首次从 0.10.5 升级到 0.10.6：** 上传开始时浏览器使用的仍是 0.10.5 旧网页，不具备本节自动确认逻辑。可以使用现有 OTA 上传，但升级重启后需重新打开/刷新页面，手动核对 0.10.6。以后由 0.10.6 页面发起的升级才具备完整自动确认。若刻意降级到不返回上述字段的旧固件，也只能人工核对，不会自动宣称成功。

## 离线验证

- `scripts/test_wifi_connection.py`：运行实际历史网络重试函数的主机替身，覆盖失联/认证失败切换、DHCP 超时、扫描占用无线模块、手机在后台尝试期间接管配网，以及配网页/设置页 JavaScript 语法。
- `scripts/test_wifi_setup.py`：运行实际试连工作函数，验证取得 IP 后才保存；认证、找不到 AP、超时、NVS 已满/写入失败保持可重试；凭据清理与无线所有权释放。
- `scripts/test_setup_page.cjs`：实际配网页脚本在离线 DOM/HTTP 替身中运行，检查自动扫描、SSID 作为纯文本、开放/隐藏网络、失败重试、断线不报成功、成功后等待用户 Finish。
- `scripts/test_ota.cjs`：镜像描述解析、设备/启动/镜像身份、同版本重新构建、启动待确认与回退。
- `scripts/test_settings_ota.cjs`：实际设置页脚本的上传进度、等待重启、有效启动、上传窗口过期、响应丢失和回退提示。

以上均不连接设备或公网服务。不能替代手机扫码兼容性、设备无线状态、完整 OTA 或断电回退测试。

## 设备按钮自动更新（0.10.7 / 服务 0.9.4）

0.10.8 修正更新入口的页面：检查、下载和结果均显示独立的 FIRMWARE 页面，不再复用 VOICE/LIVE 聊天页，也不显示录音、音量或对话提示。检查结束或失败后按 OK 返回 DEVICE 设置中的 Firmware update 项；写入成功后设备自动重启。此界面修复不代表自动更新流程已经完成实机验收。

设备联网后进入 **SETTINGS → DEVICE → Firmware update → Check / install latest**。确认会结束当前对话，然后设备自行检查发布版本、下载镜像、校验、写入另一分区并重启。已经是最新版本时显示 UP TO DATE；下载、签名、尺寸或镜像检查失败时显示可重试结果，当前启动分区不切换。更新期间保持供电，自动下载最多等待约三分钟（单次网络读取超时可能额外耗时）。

此流程不需要手机扫码、打开网页或选择文件。运行 0.10.8 及更早固件的设备可用当时的网页上传入口首次安装；0.10.9 已删除该菜单入口，恢复维护使用 USB。**早于 0.10.7 的旧设备必须先通过原网页 OTA 或 USB 安装包含按钮入口的新固件。** 当前设备已安装 0.10.9。 随后按用户要求通过 USB 完成设备首次安装 0.10.7，仅确认版本、镜像读回与启动状态；没有运行自动更新或其他功能测试。

语音服务器新增受设备令牌保护的 `GET /api/firmware/latest` 和 `GET /api/firmware/{sha256}`。固件目录由 FIRMWARE_DIR 指定，默认工作目录下 data/firmware。下载文件名是镜像 SHA-256，已经发布的镜像按哈希保留，以避免检查与下载期间新发布造成文件错配；latest.json 只指向最新发布。

发布工具检查 ESP32-C3、项目名和数值版本号，用 P-256 私钥签名规范化的项目/版本/尺寸/SHA-256。设备内只有公钥，下载前验证签名，写入后核对完整镜像哈希，再由 ESP-IDF 验证镜像并切换启动槽。签名失败、旧/同版本、被篡改元数据或不完整镜像不会进入正常升级成功路径。浏览器上传和设备自动下载共用维护锁，不能同时写入两个 OTA 操作；迟到的语音状态不会覆盖正在更新的界面。

发布新版本时必须递增 PROJECT_VER，并使用同一签名私钥：

```sh
.tools/python/bin/python scripts/publish_firmware.py \
  --image firmware/build/passport-gpt-live.bin \
  --key artifacts/auto-update-0.10.7/signing-private.pem \
  --out artifacts/menu-cleanup-0.10.9/release
```

把输出目录中的哈希命名 .bin 先同步到服务器固件目录，再更新 latest.json。私钥保存在被 Git 忽略的本地 artifacts 中，需单独妥善备份；固件与服务器下载目录不包含私钥。`firmware/main/update_public_key.h` 只保存公开验证密钥。固件镜像包含私有设备配置，下载接口不向匿名请求开放，镜像和私钥都不提交公开 Git。

自动更新的离线验证使用 `scripts/test_auto_update.py`：签名发布/篡改拒绝、匿名下载拒绝、镜像字节一致、无发布版本、数值版本排序与摘要解析；菜单主机回归覆盖确认/取消。实际设备下载、耗时、闪存写入与启动回退仍待验证。

## 0.10.9 菜单整理

DEVICE 删除 Web setup / update 及其确认页，只保留音量、亮度、熄屏时间、会话闲置时间、Firmware update 和 Back。配网统一使用 SETTINGS → Network → Connect Wi-Fi；固件升级使用独立 Firmware update 页面。更新确认和返回焦点已随菜单顺序调整。
