## 实机发现的问题与修复

- 公网 RTT 约 280 ms；默认 5760 字节 TCP 窗口不足以持续传输 48 KB/s PCM。初版持续传输静音造成音频队列积压并结束连接。
- 改为 32 KiB TCP 窗口、双端 TCP_NODELAY、仅发送非静音音频和短尾音；设备发送超时由 200 ms 改为 1 s。实机连续上传 791 帧（15.82 秒），再上传 314 帧；收到 372 帧非静音播放（约 7.44 秒），播放队列丢弃数为 0。
- 外置 WebSocket transport 默认内部处理控制帧，导致客户端心跳状态收不到 PONG、120 秒后主动断线。明确设置 `propagate_control_frames=true`；修复后连接保持超过 300 秒，无心跳断连，语音会话在空闲到期后正常回到 idle。
- 心跳修复后一次测试上传 315 帧（6.3 秒），麦克风峰值 19981，收到 258 帧非静音播放（约 5.16 秒），丢弃数为 0。设备日志位于本机 `artifacts/device-final.log`。这些数字证明数据到达音频驱动，不能代替现场听验。
- 用户现场确认可以听到播放，但存在轻微卡顿。将播放队列从 240 ms 增至 640 ms，新增 240 ms 起播/恢复预填充和 350 ms 短回复等待上限；需要确认新缓冲参数的现场效果。
