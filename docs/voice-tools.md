# 语音工具与文件上下文

实现使用 ChatGPT 订阅登录、Codex app-server、GPT-Live v3 和 WebRTC 媒体桥；当前部署记录为 Codex CLI 0.162.1。没有接入新的搜索服务、计算 API、时钟 API 或外部应用。

## 执行路径

GPT-Live 负责语音交互，查询和文件操作由 app-server 原生的 realtime handoff 转给后台 Codex。同一线程的原生 web search、命令执行和文件编辑由 app-server 执行，结果自动返回 GPT-Live。`clientManagedHandoffs=false`，无需客户端再实现一套工具路由器。客户端仍拒绝没有实现的客户端工具与交互式授权请求。

LIVE 中的简单请求沿用原生后台执行。语音提示规则要求等待工具时继续聊天，收到最终结果后在自然停顿处主动告知，不等用户追问；不主动播报步骤或进度，不为执行过程建立任务清单、进度文件或任务日志。用户要求保存的内容、明确约定的称呼和明确确认的重要长期决定可以写入文档，个人待办也可按请求记录。这是当前语音会话内的交互规则，没有新增后台任务管理或通知调度器；退出、超时或断线后的持续执行与补发通知不在此实现范围内。实际通知时机仍需通过连续对话验证。

- **联网**：显式设置 `web_search="live"`，通过内置搜索及网页读取获取资料，返回来源和日期。
- **时间**：使用本机 `date`，命令环境中的 `TZ` 来自 `VOICE_TIMEZONE`，默认 `Asia/Shanghai`。不把会话启动时间当作当前时间。
- **计算**：通过本机 `python3` 执行，金额要求使用 `Decimal`，不安装依赖。
- **文件**：持久工作目录由 `VOICE_CONTEXT_DIR` 决定，默认相对服务工作目录的 `data/context`。通过原生命令或 `apply_patch` 读写，保存后读回核验。

每个新语音会话把 `CONTEXT.md` 作为参考数据加入 v3 `initialItems`；它不替代系统指令，不触发开场。摘要最多 16 KiB，过大、非 UTF-8 或符号链接会跳过启动注入并记录原因，后台仍可按请求处理合法文件。

会话保持 `ephemeral=true`。重置、超时、断线结束本轮语音，不删除磁盘文件；用户可以通过语音修改、忘掉某条或明确清空已保存内容。不自动写入逐字转写或音频，不自动把一次性的表达风格要求当成长期偏好。保存文件是明文，应按个人服务数据进行备份。

## 轻量文档记忆

一个用户沿用同一个文件工作目录，不新增数据库、账号系统、聊天归档或定期总结任务。记录行为由语音端和后台提示规则约定，实际写入仍使用现有文件工具；没有独立的记忆提取程序。

- `CONTEXT.md`：按需保存基础印象、需要记住的事和笔记索引。基础印象区分“用户怎么称呼助手”和“助手怎么称呼用户”；未约定的不猜测、不填占位值。用户明确约定称呼即委派保存，修改时替换旧值。文件不存在时，直到第一次确有内容要保存才创建。
- 简短事项：用户说“记住、记录、保存”就写入；用户明确确认、具有后续价值的重要决定也可简短记录。普通闲聊、假设、助手建议和本轮表达要求不自动变成长期记忆。
- `notes/主题.md`：较长的讨论整理为普通 Markdown 笔记，在 `CONTEXT.md` 留下相对路径和一行说明。已有笔记按请求更新，不重复创建或强制迁移。整理时使用实际获得的讨论内容，区分已决定、建议与未定事项；没有保存的旧聊天不能恢复。
- `notes/todos.md`：用户明确要求的个人待办用 `- [ ]` / `- [x]` 记录，支持查询、修改、完成和删除。截止日期只是记录，不代表到点提醒；匹配多个事项时先澄清。
- 保存与忘记：写入后读回核验正文和索引，再播报成功。忘掉一条时清理相关笔记中的该条内容与摘要引用，保留其他记录；删除文档时移除索引。重置当前聊天仍保留文件。

这些相对路径均位于 `VOICE_CONTEXT_DIR` 内。文件按需创建，不预写示例称呼或个人资料。助手只承担简单查询、记事和文档整理，超出范围的任务可帮助记录需求，不展开大型开发、长期研究或复杂自动化。

## 运行边界

app-server 使用命名权限配置 `mic-on`：`:minimal` 只读、`:workspace_roots` 可写、工作目录下 `.codex` 只读、命令网络关闭。命令环境只提供工具搜索路径和时区，不继承设备令牌等服务变量。托管 web search 独立于命令网络权限。服务器 Codex 自己仍使用现有订阅登录进行模型与搜索请求。

使用 wrapper/npm 安装 Codex 时，其沙箱执行程序可能位于系统运行目录之外，需设置 `VOICE_CODEX_RUNTIME_DIR` 为实际 Codex 安装目录。当前服务器记录为 `/home/lake/.nvm/versions/node/v24.15.0`，只额外授予该安装目录读取权限。遗漏此配置时，语音和搜索可能仍可工作，但本机命令会报 `bwrap: execvp ... codex: No such file or directory`。`thread/start` 必须保留默认本机环境；显式传 `environments: []` 会移除命令工具。

工具请求增加后台推理与工具等待时间，使用同一个订阅的额度。音频流继续运行；工具完成不等于扬声器已播完。原有 VOICE 发送控制、LIVE 收音、停止播放和音色逻辑继续由现有链路处理。

`RUST_LOG=passport_voice=info` 记录 `voice backend tool`，只含工具类型及开始/完成事件，不记录用户查询、执行命令、文件内容或工具结果。原生工具能力及权限配置仍依赖实验性 app-server 版本，应在升级 Codex 时复验。
