## 首页切换后二次跳动修复

用户反馈“已经切换，然后文字又抖一下”。原因是旧动画立即更新 home_selected（颜色与原选中项字号立即变化），但新选中项使用 160 ms 行高插值，等高度达到 92 px 才切到 80/52 px 字体，并附带最多 3 px 的横移。离散字体切换和连续行高插值不同步，导致明显的第二次跳动。

修复为一次提交选中项和最终行高，删除行高动画与文字横移，仍保留选中项的大字布局。没有提高 SPI 时钟、增大 DMA 缓冲或修改语音任务。离线分别检查两次选中后的十帧（20 ms 间隔），每组像素哈希完全一致，无延迟变形；62 个渲染状态无裁切，100 次导航无泄漏。

另外，当前固件 LVGL 刷新周期为 33 ms（目标约 30 Hz），SPI 为 40 MHz、RGB565、20 行单缓冲。面板初始化注释的 60 Hz 不能代表整条绘制链路达到 60 fps。本次修复针对已确认的二次视觉跳动，并未测量实机按键到像素的延迟或实际帧率。

## 音色选择保持原页及界面稳定性回归

移除音色保存后 menu_back，以及 new_conversation(true) 对设置导航状态的清除。设备音色页或手机设置页保存音色时停止旧会话，保留页面；即使停止确认、断网恢复等异步事件要求重建会话，start_session 也会等待用户主动离开设置进入聊天。重复确认当前音色不保存、不导航。明确的 Reset context 仍执行原有新聊天流程。

检查并修复连接提示被随后 ui_show_guide 覆盖的问题，先建立语音页再显示连接状态；重复相同状态不再主动使图案区域失效。

菜单回归通过；scripts/test_voice_navigation.py 提取真实会话转换函数，用主机桩验证菜单、手机设置、连续换音色、断网、主动进入聊天及明确重置流程。实际 LVGL 渲染覆盖 66 个状态，0 文字裁切，100 次导航无泄漏。保存音色、重复确认、后台重连事件三种画面像素完全一致，二维码页收到后台状态后也保持像素一致。证据在 artifacts/voice-picker-fix/。主机验证不替代物理按键操作验收。

## 2026-10-10 音频驱动图案动画

保留原圆环麦克风和圆形声波。Voice 彩色弧线随音量伸缩，话筒与圆环位置固定；Live 九根圆角声波柱高度随音量变化，并叠加轻微错相起伏，静音时收回到短柱。颜色与原有对话状态一致。

音频任务通过无锁原子快照提交电平，不操作 LVGL、不分配内存。麦克风使用实际上传前 PCM，回复使用增益处理后、成功送往 I2S 的 PCM；SPEAKING 状态选择输出电平，其余录音/聆听状态选择输入电平。每四个样本抽取一个，去直流后计算平均绝对幅度，经过小噪声门限与饱和映射。180 ms 未更新视为静音，再平滑衰减。此图形为音量反馈，不是频谱分析。

LVGL 定时器周期 80 ms（目标 12.5 次/秒），上升快、下降慢。仅使中央 117 × 115 px 图案区域失效；文字、标题、按钮说明布局不参与动画。菜单、二维码、息屏时停止图案刷新，重新进入聊天清除旧电平。

桌面真实 LVGL 渲染覆盖 163 帧/状态，检查噪声/DC 抑制、输入输出隔离、静音与过期衰减、柱高边界、文字逐像素不变、菜单和息屏停动。0 文字裁切，100 次导航无泄漏（LVGL 空闲 6568 bytes）。音色选择保持原页回归通过。artifacts/audio-animation/preview.gif 使用合成 PCM 展示运动，不代表实机录屏或实测帧率。

ESP-IDF v5.5.3 编译通过，应用 1,599,792 bytes，已写入 ota_0（0x10000）并通过 esptool 哈希校验。重启后设备返回 NAVIGATION、alloc_failures=0，音量/音色/亮度/息屏/空闲/双工设置与刷前一致。完整记录在 artifacts/audio-animation/manifest.json、flash.log 和前后设备快照。实际声音驱动的观看体验、实测帧率与音质仍需现场体验。
